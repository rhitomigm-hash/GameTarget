# マーカー回収レース（自由走行の第1段階）

`/prototype/` または `/prototype/?mode=chase` で回収ゲームを開始。`a`・`w`・`setup` は設定と併用できる。旧 `dev=1` は回収用設定へ接続する。
操縦用の旧処理は移行確認用の `mode=flight` で保持している。
`mode=chase` では道路を読み込み、同じチームの白い追尾車と青い先行車を生成する。
白は気球を追尾、青はターゲット100m以内へ入らず近づける道路で待機する。
黄色は引き続き自由走行。道路・クルーの物理は気球の飛行に影響しない。

## チームと得点（2026-09-15）

- 回収成功1,000点、黄色の道路走行100mにつき1点（仮の配点）。
- 往復・周回も加点する。距離の端数を積算し、点数は整数切り捨て。
- 着地または時間切れで道路加点終了。時間内投下ならその後も着地まで回収を続ける。
- 結果は回収点・道路走行点・合計と距離を表示。距離の自己ベストは別に維持する。
- 道路判定は中心線と幅員区分による近似。交通法規を守ったかの判定ではない。
- 読み込み済み道路のみ加点し、高速道路は対象外。未読区間を後から加点はしない。
- 一時停止で気球・3台の車・マーカー・時計・加点・音を停止。俯瞰とパネルは操作できる。
- `node experiments/chase-mode/verify-score.mjs` で距離と採点の境界条件を確認する。

- WASD / 矢印: 前後・ハンドル。進行方向と逆の入力でブレーキ。
- V: 車の後方から進行方向を見る / 気球を見る。
- 「俯瞰」ボタン: 気球・車・投下済みマーカーを南側の斜め上から見る。
  もう一度押すと直前の運転視点へ戻る。Vの2視点とは独立している。
  俯瞰中にVを押すと運転へ戻って2視点を切り替える。
- 回収モードの計器・回収情報・パイバル・操作説明・出典は最初は折りたたむ。
  見出しで個別に開閉でき、「まとめてたたむ → 元に戻す」は開閉状態を復元する。
  全て閉じた初期状態では「パネルを開く」でまとめて開ける。
- P: パイバル表。1–4: 時間加速。タッチ端末は画面のボタンで操作。
- 気球は自動操縦し、ターゲット400m以内・対地10m以上でマーカーを投下する。
- **着地の瞬間**に車がマーカーから30m以内なら回収成功。着地後に拾いに行く方式ではない。
- 30m・400m・10m等は試作ゲームの調整値で、実競技の規則・安全基準ではない。
- 黄色は道路・水域・建物の通行制約なし。地形の範囲から車は出さない。
- 簡易自動操縦なので目標への到達を保証しない。未投下での時間切れ、燃料切れ接地、範囲外で終了。
  制限時間内に投下できた場合は、時間切れ後も着地まで回収を続ける。

## 添付案からの補修

`playerCar.js` は生成時から地形境界を適用し、境界では停止する。道路表示には依存しない。
近距離開始では初期車間を縮める。`balloonAutopilot.js` は地形より上の候補高度を選び、
`shouldDrop()` が要求した投下が実際に成功した後で `markDropped()` を呼ぶ。
車・気球・マーカーを同じ小刻みの時間で進めて着地時の位置を計測する。

気球の `stepPhysics`・`windAt`、マーカーの `dropMarker`・`stepMarker` の計算は変更していない。
回収モードだけ入力・更新順・カメラ・終了・成績保存を分けている。
自己ベストは `balloon-chase-proto-best` に保存し、JDGの記録を使わない。

## 検証

リポジトリのルートで `python -m http.server 8000 --bind 127.0.0.1` を起動し、
Playwrightが利用できる環境で `node experiments/chase-mode/verify.mjs` を実行する。
必要なら環境変数 `CHASE_PLAYWRIGHT` にPlaywrightパッケージの絶対パスを指定する。
地理院タイルと既存のThree.js CDNに接続できることが必要。

チーム・加点の検証も同じスクリプトに含む。実道路上の走行距離と加点距離の一致、
時間切れ直前の部分加点とその後の締切、成功1,000点/失敗0点、3台の一時停止を確認する。

試験用のアクセス口はブラウザへのレスポンスにだけ追加し、本体ファイルには書き込まない。
実装の入力・成功/失敗判定・未投下時間切れ・成績分離・境界・高地の候補選択を確認し、
20m/400m開始・既定風・無風を実DEM上で走らせる。既定風は×1/×8相当の刻みを比較する。
`?mode=flight` と、それに `setup=1` / `a=130.25,33.27` / `dev=1` を組み合わせた旧操縦の起動・手動バーナーと、
タッチ端末エミュレーションでのボタン入力も確認する。
スクリーンショットは `tmp/chase-verification/` に出力する。実機スマホは別途確認が必要。
`CHASE_VERIFY_OUT` / `CHASE_ENTRY_OUT` に末尾 `/` 付きのリポジトリ相対パスを指定すると、各検証の出力先を変更できる。

俯瞰の追加検証: 近距離・3km・16kmの離隔で対象の画面内収まり、マーカーの目印、
元の視点への復帰、パネル開閉状態の復元、スマホの縦横画面でボタンと運転操作が
重ならないことを確認する。俯瞰はカメラ・霧・目印だけを変更し、運転へ戻す際に復元する。

## 入口の整理（2026-09-17）

通常の入口はすべて回収ゲーム。`verify-entry.mjs` で既定・setup・a・dev・mode=chase、操作案内、SORAリンク、スマホ画面を確認する。
`verify.mjs` は従来の回収・採点の検証を維持し、旧操縦側の回帰確認だけ `mode=flight` を明示する。
